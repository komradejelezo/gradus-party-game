# ГРАДУС · GRADUS Party Game

Готовый локальный MVP русскоязычной настольной игры для компании 2–15 взрослых. React + TypeScript + Vite. Отдельный Git-репозиторий `gradus-party-game`; без сервера, учётных записей и внешних ресурсов.

## Запуск

Нужен Node.js 22+ и npm.

```bash
cd gradus-party-game
npm ci
npm run dev
```

Откройте адрес, показанный Vite (обычно `http://localhost:5173`). Для планшета в той же сети используйте сетевой адрес компьютера. Для установки PWA на удалённом устройстве нужен HTTPS: обычный HTTP по LAN подходит для игры, но браузер не разрешает service worker. На localhost HTTPS не требуется.

Проверка готовой сборки и офлайн-режима:

```bash
npm run build
npm run preview
```

Откройте `http://localhost:4173`, дождитесь первой загрузки, затем отключите сеть и перезагрузите вкладку. Офлайн-кеш включён только в готовой сборке. Service worker кеширует всё приложение и добавленные локальные аудиофайлы. При изменении ресурсов сборка создаёт новую версию кеша. `dist/` можно разместить на статическом HTTPS-хостинге. Не открывайте `index.html` через `file://`.

## Что можно играть

- Полный цикл от создания игроков и объяснения правил до «Последнего градуса» и победы.
- Извилистая дорожка из ровно 30 клеток: 10 «Голос», 10 «Тело», 10 «Хаос».
- 39 разных карточек, по 13 в каждой категории; финальная карточка отдельно. 17 карточек с тегом застолья/тоста.
- D6, поэтапное движение, базовые и особые эффекты, дуэли, личная и случайная подстава.
- Локальное сохранение после каждого действия; продолжение с раскрытой/переданной карточки; отмена до 20 последних действий, включая после перезагрузки.
- Вспомогательный таймер, две временные памятки, отдельные настройки музыки, эффектов, голоса и общего отключения звука.
- Адаптация для горизонтальных планшетов и телефона, сокращение анимаций по системной настройке. Несколько фишек на клетке сгруппированы: три номера и счётчик, все игроки и позиции доступны в списке справа/снизу.

Данные сохраняются в браузере на текущем устройстве (`gradus-save-v1`, `gradus-audio`). Очистка данных сайта удалит партию. При недоступном хранилище показывается сообщение, игра остаётся доступна до закрытия вкладки.

## Архитектура

```text
src/game-engine/  Чистые функции правил, типы состояния, проверка сохранения
src/content/      Поле, категории, 39 печатных карточек и финальная карточка
src/ui/           Экраны, диалоги, анимация движения, вспомогательный таймер
src/audio/        Локальный проигрыватель, приглушение музыки, настройки
public/audio/     Слоты для собственных MP3
public/sw.js      Шаблон service worker; список кеша создаётся при сборке
scripts/          Экспорт карточек для подготовки физической игры
```

`createGame`, `roll`, `sabotage`, `resolve`, `next`, `dismissReminder` возвращают новое состояние. Случайность передаётся в `roll` отдельно, что позволяет воспроизводить тесты. Бросок кубика в UI использует криптографический генератор с отбрасыванием смещённых значений. Нажатия на время движения блокируются. Правила бонусов, штрафов, передачи и финала находятся только в движке.

## Принятые решения

- Голосование: большинство голосов, при ничьей — в пользу исполнителя. Дуэли и угадывания оценивает компания по тексту задания. Все действия добровольны; отказ — кнопка «Провал».
- Личная подстава заменяет **весь** эффект обычной карточки своей фиксированной схемой; случайная цель «Хаоса» при этом не используется. Для этих карточек есть отдельный короткий текст после передачи (`transferInstruction`).
- Если адресат личной или случайной подставы достиг 30, его финал проходит до перехода к следующему ходу. Порядок ходов сохраняется. При одновременном финише двух участников первым проходит финал активный игрок. Победа завершает партию сразу; после неудачи следующий ожидающий проходит свой финал.
- Бонус/штраф не открывает новую карточку. Достижение 30 даёт только финальную карточку; личный жетон на неё не действует. Провал финала перемещает на 27.
- Колоды независимы; использованные ID сохраняются. После исчерпания соответствующей категории начинается новый цикл; на границе циклов повтор допустим.
- Временные эффекты — только памятки без дополнительных автоматических штрафов. Показаны срок и кнопка завершения. При появлении третьей памятки самая старая заменяется. Ведущий закрывает памятку после следующего хода.
- Таймер не выносит вердикт и при перезагрузке/передаче карточки начинается заново; состояние самого задания и выбранный исполнитель сохраняются.
- Аудио необязательно. Лицензионные MP3 в MVP не поставляются. Отсутствующие файлы не запрашиваются; ошибки проигрывания и блокировки автозапуска не мешают игре. Короткие сигналы генерируются Web Audio локально. После добавления MP3 нужна новая сборка. Требования — в `AUDIO_ASSETS.md`.

## Проверка

```bash
npm test
npm run build
npm run export:content
```

Тесты движка проверяют размеры партии, поле, уникальность карточек, отсутствие повторов, дуэли, эффекты «Хаоса», границы 0/30, оба вида подставы, финал после броска и бонуса, финал адресата, очередь двух финалистов, памятки, 15 игроков, восстановление и полную партию.

Браузерные тесты запускаются против готовой сборки:

```bash
npx playwright install chromium
npm run build
npm run test:e2e
```

Если Chromium уже установлен, можно указать путь:

```bash
CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e
```

Проверяются создание партии, бросок и передача, перезагрузка во время задания, отмена, 15 игроков на одной клетке, размеры 1024×768 / 1280×800 / 390×844, офлайн-перезагрузка и ход без MP3, полный игровой цикл до победы и финал адресата подставы. Автоматические браузерные проверки выполнены в Chromium; проверка на физических iPad/Android остаётся перед выпуском на устройства.

## Экспорт для настольной версии

```bash
npm run export:content
```

В `exports/` появятся `gradus.json` (поле, карточки, финал) и `gradus.csv` (UTF-8 с BOM, разделитель `;`, финал отдельной строкой). Сохраняются ID, категория, название, инструкция, способ проверки, время, участники, формализованный эффект, тег тоста. Макеты печати не входят в MVP.
